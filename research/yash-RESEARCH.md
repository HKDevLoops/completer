## 1. Config / RC path

- **POSIX (documented, from the official README):**
  - Login shell: `$XDG_CONFIG_HOME/yash/profile`, fallback `~/.yash_profile`.
  - Interactive: `$XDG_CONFIG_HOME/yash/rc`, fallback `~/.yashrc`.
  - Verbatim: *"When yash is started as a login shell, it reads `$XDG_CONFIG_HOME/yash/profile` or
    `~/.yash_profile` as a fallback."* and *"When yash is started for an interactive use, it reads
    `$XDG_CONFIG_HOME/yash/rc` or `~/.yashrc` (after reading ... profile if it is a login shell also)."*
    — https://github.com/magicant/yash (README, "Initialization scripts")
  - Verbatim from the manual: *"the shell reads [$XDG_CONFIG_HOME]/yash/rc or [~]/.yashrc as a
    fallback. If it cannot be read, the shell searches [`YASH_LOADPATH`] for a file named
    initialization/default."* — https://magicant.github.io/yash/doc/invoke.html#init
  - *"If the [`XDG_CONFIG_HOME` environment variable] is not set, [~]/.config is used as the default
    location."* — same URL. So the default is `~/.config/yash/rc`.
  - Explicitly: *"Yash never automatically reads /etc/profile, /etc/yashrc, nor [~]/.profile."* — same URL.
  - Options to override: `--profile=filename`, `--rcfile=filename`, `--noprofile`, `--norcfile` — same URL.
- **Windows:** no config path documented. Yash is a POSIX.1-2001 shell in C99; *"Currently, yash is
  mainly tested on Fedora and macOS"* — https://github.com/magicant/yash (README, Requirements).
  → GAPS.

## 2. Native completion API

- **The `complete` builtin** (elective, "L") — verbatim syntax and description:

  ```
  complete [-A pattern] [-R pattern] [-T] [-P prefix] [-S suffix] [-abcdfghjkuv] [[-O] [-D description] word…]
  ```

  > "The complete built-in generates completion candidates. This built-in can only be executed from
  > completion functions during command line completion. ... The built-in generates completion
  > candidates according to the specified arguments. No matter how candidates are generated, only
  > candidates that match the word being completed are generated."

  Candidate-type flags include `-a/--alias`, `-b/--builtin-command`, `-c/--command`, `-d/--directory`,
  `-f/--file`, `-g/--group`, `-h/--hostname`, `-j/--job`, `-k/--keyword`, `-u/--username`,
  `-v/--variable`, plus `--function`, `--external-command`, etc. Operands are treated as completion
  candidates. — https://magicant.github.io/yash/doc/_complete.html
- **Completion functions (registration mechanism)** — verbatim from the manual:

  > "Normally, command names are completed with command names and command arguments with pathnames.
  > However, completion functions can be defined to refine completion results. ... When completing a
  > command name, the shell executes the `completion//command` function and when completing a command
  > argument, the `completion//argument` function. If those completion functions are not defined, the
  > shell just completes with command names or pathnames. ... Completion functions are executed
  > without any arguments. The following local variables are automatically defined while executing
  > completion functions: [`IFS`] ... [`WORDS` — array whose elements are a command name and arguments
  > that have already been entered before the argument being completed] ... [`TARGETWORD` — the
  > partially entered command name or argument that is being completed]. Completion candidates are
  > generated by executing the complete built-in during a completion function."

  — https://magicant.github.io/yash/doc/lineedit.html#completion-detail
- Auto-loading bundled completion scripts — verbatim:

  > "When doing completion for the first time after the shell has been started, the INIT file is
  > loaded as if the command string `.  -AL completion/INIT ` is executed. If the file is not found,
  > it is silently ignored. This automatic loading is mainly intended for loading completion
  > functions bundled with the shell, but you can let the shell load your own functions by putting a
  > file in the [load path]."

  — https://magicant.github.io/yash/doc/lineedit.html#completion-detail
  The README confirms: *"Command line completion with predefined completion scripts for more than
  100 commands"* — https://github.com/magicant/yash (README).

## 3. Alias add / remove (native mechanism)

Verbatim from the official alias builtin page:

```
alias [-gp] [name[=value]…]
```
"The alias built-in defines and/or prints aliases as specified by operands. ... The built-in prints
all currently defined aliases when given no operands."
Operands: `name` (print), `name=value` (define). Options: `-g/--global` (global aliases),
`-p/--prefix` (print in `alias -g foo='bar'` form).

— https://magicant.github.io/yash/doc/_alias.html

Removal: the `unalias` builtin exists and is a **mandatory** builtin (marked "(M)") in the official
builtin list — https://magicant.github.io/yash/doc/ (Built-ins, "Aliases" category:
`alias` (M), `unalias` (M)). Per-builtin page: https://magicant.github.io/yash/doc/_unalias.html
(not fetched; existence and type are cited from the official index).

## 4. Sourcing a generated file

The dot builtin is the sourcing mechanism; it is a special builtin —
https://magicant.github.io/yash/doc/ (Built-ins: *"`.` (dot)" (S)*, page
https://magicant.github.io/yash/doc/_dot.html). Verbatim usage in the completion docs is the
auto-load form: `.  -AL completion/INIT ` — https://magicant.github.io/yash/doc/lineedit.html#completion-detail
(`-AL` are the dot builtin's options for alias loading; full flag semantics on the dot builtin page,

## 7. Self-completion (completion for the shell's OWN `completer` function)

**Feasible per the documented API, but no verbatim self-completion snippet is published.**
The shell calls the generic `completion//argument` function for *every* command argument and exposes
the `WORDS` array (command name + prior arguments) and `TARGETWORD`, so a completion function can
branch on `$WORDS[1] == completer` and emit candidates via `complete`. All of those facts are quoted
verbatim in §2 (https://magicant.github.io/yash/doc/lineedit.html#completion-detail,
https://magicant.github.io/yash/doc/_complete.html). There is **no** per-command registration builtin
and **no** official example showing a conditional on the command name → the exact snippet would be
inference, so it is not claimed here. GAPS.
